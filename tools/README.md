# Tools

Site and branding helpers. The game's own assets are generated by the scripts under `scripts/`
(see the README at the root); these are for the icons, the box art and sprite pack zips.

## logo-gen.html

Draws the logo, the favicon frames, the maskable icon and the social card. Open it through a
local web server that accepts `fetch` POSTs (a plain `file://` open draws but does not save),
then run `generate()` in the browser console. It writes `sunspire-logo-512.png`,
`sunspire-mark-512.png`, `sunspire-maskable-512.png`, `sunspire-card.png` and the
`favicon-16/32/48/180/256.png` frames; copy them to `static/icons/` (and rebuild the favicon).

A one-line server that accepts those POSTs:

```js
// save-server.js — serves the current folder and writes POSTed PNG data URLs to disk
const http = require('http'), fs = require('fs'), path = require('path');
http.createServer((q, s) => {
  if (q.method === 'POST'){ let b = []; q.on('data', c => b.push(c)); q.on('end', () => {
    const m = Buffer.concat(b).toString().match(/^data:image\/png;base64,(.*)$/);
    fs.writeFileSync(q.url.replace(/[^a-z0-9_.-]/gi, ''), Buffer.from(m[1], 'base64')); s.end('ok'); }); return; }
  fs.readFile(path.join(process.cwd(), q.url.split('?')[0]), (e, d) => { if (e){ s.statusCode = 404; return s.end(); }
    s.setHeader('Content-Type', q.url.endsWith('.html') ? 'text/html' : 'application/octet-stream'); s.end(d); });
}).listen(8138);
```

## build-ico.js

Assembles `favicon.ico` (16, 32, 48 and 256 px frames) from the PNGs above. The pages link
`static/favicon.ico` and `static/icons/sunspire-mark-512.png` (apple-touch-icon).

## make-pack-zip.js

Builds a sprite pack zip players can load with *Load sprite pack* (see `packs/README.md` and the
pack guide page); a folder's `<slot>.json` atlases go in with its sheets. Without arguments it
exports every built-in sheet listed in
`static/pack-slots.json` to `sunspire-engine-pack.zip` at the repository root: a complete
reference pack and a template to redraw from. Its sheets are the built-in art itself, so loading
it unchanged alters nothing on screen; redraw a sheet to see the pack take effect. With a folder (and optionally an output name) it
zips that folder's PNG / GIF / WebP files instead:

```bash
node tools/make-pack-zip.js
```

```bash
node tools/make-pack-zip.js my-pack/ my-pack.zip
```

Zips at the root are git-ignored; share them as release assets or from a separate repository.

## make-upstream-pack.js

Builds a sprite pack out of the upstream engine repository's own sprites (the `upstream` git
remote), re-cut into Sunspire's sheet layout, for your own browser only: those sprites are not
free to redistribute, so the output folder and the zip are git-ignored and must stay out of the
repository and out of any pack you share.

```bash
node tools/make-upstream-pack.js
```

```bash
node tools/make-pack-zip.js pack-upstream sunspire-upstream-pack.zip
```

The sprites are read straight out of git. For every slot with an upstream counterpart the tool
lays the upstream frames out in a new sheet at their own size, under Sunspire's frame names, and
writes the `<slot>.json` atlas the pack loader accepts next to it; frames without a counterpart
keep the built-in art. With `--fit` it keeps the built-in sheets instead and shrinks each
upstream frame into its Sunspire cell (upstream frames are 32x32 or 64x64 against Sunspire's
16x22 and smaller), nearest-neighbour or averaged with `--smooth`. The
mapping table at the top of the script says which upstream sheet stands in for which Sunspire
character, enemy, spirit and icon; upstream has fewer of each, so several share a source. The
trees and fence pieces are sprites of their own in the engine build, so they come over at
native size (the trees shrunk to two tiles wide, as the maps plant a tree on every single
tile); the tilesets, the houses, the map objects (sign, well, gate, marker, spring, crate), the
summon backdrops and the shadow stay built-in. `REPORT.txt` in the output folder lists what was
replaced.

Upstream has no bat, so the bat is cut out of `pack-upstream-extra/enemies.png` when that file is
there (another folder with `--extra`), and takes the `momonga` otherwise. That is the 297x1113
ripped enemies sheet with no alpha channel whose ninth block is the Bat (Vermin, Wild Mushroom,
Slime, Zombie, Skeleton above it), saved under that name; the rects in the script are its
pixel positions, and its most common colour is keyed out as the background. The bat idles with
spread wings, winds up with a cocked wing and dives to attack, raises a wing and swipes to cast,
and wraps its wings when hit, front and back, every pose in a 32x32 frame at the same hover
height. The folder is git-ignored like the pack, for the same reason.

## Box art, concept sheets and screenshots

`assets/art/` (box front, back and spine, the four concept sheets, the hero portraits) and
`assets/screens/` (the in-game screenshots on the landing page) were drawn from the
single-script game's sprites by `promo-gen.html` on the `main` branch, which needs that game's
`game.js`. They are kept as they are here; redraw them from the engine build when its art has
moved on.
